# AGENTS.md

AllyMailer Spring Boot — Spring Boot integration of the AllyMailer Java SDK (``) for the AllyMailer transactional email Web API (Web API 1.90).

## Working on this repository

- **Generated code.** The whole package is generated by the AllyMailer team from the AllyMailer Web API OpenAPI spec (Web API 1.90): sources, docs, README.md and this file. Do not hand-edit it: the next release replaces the content of this repository. Report problems and requests in the issues of this repository (https://github.com/allymailer/allymailer-spring).
- **Build and check:**

  ```bash
  mvn -q -DskipTests package
  ```

- **Source label.** Every request carries the query parameter `platform=spring.2.0.0,java-sdk.2.0.0` (this package, then the SDK it is built on).
- **Tests.** Before a release the generator installs the package into a test app of Spring Boot and checks the client, the webhook endpoint and the mailer against a mock of the API: no real API key, no real sends.
- **Release.** The version (2.0.0 in pom.xml) and the tag `v2.0.0` come from the generator; README.md states the Web API version the release was generated from.
- **Secrets.** Never commit API keys; the examples read `ALLYMAILER_API_KEY` from the environment.

## Integrating AllyMailer with this package

Full guide: [README.md](README.md). Spring Boot integration of the [AllyMailer Java SDK](https://github.com/allymailer/allymailer-java-sdk) (``): the API client in the application context (auto-configuration), a webhook endpoint with signature check, a JavaMailSender transport that sends through `email/send`.

Install:

```bash
# pom.xml
<dependency>
    <groupId>ua.com.allymailer</groupId>
    <artifactId>allymailer-spring-boot-starter</artifactId>
    <version>2.0.0</version>
</dependency>
```

Requirements: Java 17+, Spring Boot 3.

Rules that generated code must follow:

- Server-side only. Read the API key from `ALLYMAILER_API_KEY`; never put it in browser or mobile code, never commit it.
- Base URL `https://cp.allymailer.com/ua/transactional/api/v1`; every method is POST with a JSON body; auth header `X-API-KEY`. The package does all of it.
- First email without DNS: `domain/get-sandbox-domain` → `confirmed-email/create` (the user clicks the link within 48 hours) → `email/send` from `noreply@<sandbox-domain>` to the confirmed address. Account API key only; up to 10 confirmed addresses, 100 emails a day; the domain expires after 31 days.
- Never ship a sandbox domain as the production sender (it is not in `domain/list`); read `from_email` from config. Production needs a verified domain: `domain/get-dns-records` → DNS records → `domain/validate-verification-record`, `domain/validate-dkim` → `domain/list`.
- Set `message.idempotence_key` on retryable sends; retry network errors, `429` and `5xx` with backoff, not other errors unchanged. Up to 500 recipients and 10 MB per request, each attachment up to 7 MB; always `body.html` or `body.plaintext`.
- Delivery events via webhook (`webhook/set`), not polling; the webhook endpoint of this package checks the `auth` signature of every notification.
- Keep the default unsubscribe and tracking behaviour; changes go through AllyMailer support.
- Do not invent methods or fields. Check the [README](README.md), the [API reference](https://docs.allymailer.com.ua/ua/web-api-ref) or [llms.txt](https://docs.allymailer.com.ua/llms.txt).

### Configuration

The API key goes to `ALLYMAILER_API_KEY`.

```yaml
# application.yml (or the ALLYMAILER_* environment variables)
allymailer:
  api-key: ${ALLYMAILER_API_KEY}
  host: cp.allymailer.com
  timeout: 30
  webhook:
    path: /allymailer/webhook
  mail:
    enabled: true
```

| Option | Environment variable | Default | Description |
|---|---|---|---|
| `allymailer.api-key` | `ALLYMAILER_API_KEY` |  | User or project API key (required). |
| `allymailer.host` | `ALLYMAILER_HOST` | `cp.allymailer.com` | API host (datacenter: `cp.allymailer.com`) or a full base URL. |
| `allymailer.timeout` | `ALLYMAILER_TIMEOUT` | `30` | Request timeout, seconds. |
| `allymailer.webhook.key` | `ALLYMAILER_WEBHOOK_KEY` |  | API key the webhooks are signed with (the key of the user/project of the webhook), if it differs from the API key. |
| `allymailer.webhook.path` | `ALLYMAILER_WEBHOOK_PATH` | `/allymailer/webhook` | Path of the webhook endpoint. |

### Sending mail

Messages of the JavaMailSender go through [email/send](https://docs.allymailer.com.ua/ua/web-api-ref#email-send): from, to/cc/bcc, reply-to, subject, HTML and text parts, attachments, inline images and `X-*` headers.

```java
@Autowired
private JavaMailSender mailSender;

MimeMessage message = mailSender.createMimeMessage();
MimeMessageHelper helper = new MimeMessageHelper(message, true);
helper.setFrom("shop@example.com", "Shop");
helper.setTo("user@example.com");
helper.setSubject("Order shipped");
helper.setText("<b>Your order is on the way</b>", true);
message.setHeader("X-Order", "42");
mailSender.send(message);
```

### Webhooks

The endpoint answers `GET` with 200 OK (the URL check of [webhook/set](https://docs.allymailer.com.ua/ua/web-api-ref#webhook-set)) and accepts the `POST` notifications: it checks the `auth` field (MD5 of the request body in which the `auth` value is replaced by the API key), answers 401 to a wrong signature, and passes the notification and each of its events to the application.

```java
import ua.com.allymailer.wrapper.WebhookEventReceivedEvent;

@Component
public class DeliveryListener {
    @EventListener
    public void onEvent(WebhookEventReceivedEvent e) {
        var data = e.getEvent().getEventData();
        log.info("AllyMailer event {}: {} {}", e.getEvent().getEventName(), data.getEmail(), data.getStatus());
    }
}
```

Register the URL of the endpoint with `webhook/set`, e.g. `https://example.com/allymailer/webhook`.
